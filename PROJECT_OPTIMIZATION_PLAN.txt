米家中枢屏幕工作台 - 当前状态与优化目标
========================================

一、项目定位
------------
本项目是面向 VIEWE UEDX80480070E-WB-A 开发板的中文可视化 ESPHome/LVGL 配置、编译和烧录工具。
目标硬件为 ESP32-S3-N16R8、800x480 RGB 屏幕和 GT911 触摸控制器。
软件通过本地 Web 工作台完成界面设计，调用当前 Python 环境中的 ESPHome 生成、校验、编译并烧录固件。

二、当前已有功能
----------------
1. 800x480 可视化画布，支持 60%、80% 和 100% 缩放。
2. 图形与图片组件：矩形、椭圆、圆形、线条、静态图片及叠加文字。
3. 状态组件：圆形状态栏和柱状状态栏。
4. 虚拟按钮：页面切换和 Home Assistant 操作调用。
5. 多界面管理、鼠标滚轮切换界面和组件层级调整。
6. 组件拖拽、缩放、属性编辑、图片裁切和图片预处理。
7. Home Assistant 数值实体、状态实体和服务操作绑定。
8. ESPHome YAML 生成、配置校验、编译、串口扫描和固件烧录。
9. 浏览器端项目自动保存、任务进度和实时日志。
10. PNG、JPEG、WebP 和 BMP 静态图片支持。

三、当前主要不足
----------------
1. 缺少多选、对齐、吸附和完整图层管理。
2. 烧录流程缺少分阶段进度、失败重试、烧录后验证和固件版本确认。
3. 缺少 OTA 更新和局域网设备发现。
4. 缺少独立串口监视器、日志过滤和诊断报告。
5. 缺少显示测试、触摸坐标测试和校准工具。
6. 缺少图片、字体、固件、Flash、RAM 和 PSRAM 资源占用预估。
7. Home Assistant 实体仍以手工输入为主，缺少实体发现、搜索和属性选择。
8. Wi-Fi、API 和 OTA 密钥的日志保护需要继续加强。

四、总体优化目标
----------------
将当前工具从“可视化配置和基础烧录工具”完善为覆盖以下生命周期的开发板工作台：

项目创建 -> 界面设计 -> 硬件配置 -> 配置校验 -> 资源分析 -> 固件编译 -> USB 烧录 -> 烧录验证 -> 串口诊断 -> OTA 升级 -> 设备维护

优化必须遵循以下原则：
1. 优先提高可靠性和可恢复性，再扩充组件数量。
2. 保持项目文件向后兼容，数据模型变更必须提供迁移或默认值。
3. 高风险操作必须明确显示目标设备并要求确认。
4. 面向普通用户显示中文错误提示，同时保留原始技术日志。
5. 密钥和密码不得出现在普通日志、诊断包或默认项目导出文件中。
6. 新功能必须有针对性的自动化测试，并通过前端语法和后端测试。
7. 继续使用现有 Web 工作台、Python 本地服务和 ESPHome 工具链，不重复实现编译内核。

五、分阶段实施计划
------------------

第一阶段：可靠性与项目安全
1. 项目格式版本号和兼容迁移。
2. 项目导入、导出、备份和恢复。
3. 编辑器撤销、重做和崩溃恢复。
4. 配置完整性检查：越界、重复 ID、缺失资源和无效实体格式。
5. 敏感字段脱敏及安全导出。
6. 烧录前设备确认和烧录后验证。
7. 编译、烧录错误分类及中文建议。

第二阶段：设备与调试能力
1. 读取芯片型号、MAC、Flash、PSRAM 和设备标识。
2. 独立串口监视器、搜索、级别过滤、保存和自动重连。
3. 显示纯色、棋盘格、边缘和背光测试。
4. 触摸坐标、轨迹、方向和边缘测试。
5. 一键生成脱敏诊断报告。
6. 图片、字体、固件和内存资源分析。

第三阶段：编辑效率
1. 多选、框选、复制、粘贴、锁定和隐藏。
2. 网格吸附、辅助线、对齐和等间距分布。
3. 页面缩略图、复制、排序和默认启动页。
4. 组件模板：温湿度、灯光、空调、门锁和系统监控。
5. 图层树和组件搜索。

第四阶段：联网维护与智能家居增强
1. ESPHome OTA 更新和局域网设备发现。
2. 多设备管理、固件版本比较和升级记录。
3. Home Assistant 实体发现、搜索、属性选择和服务调用测试。
4. 条件显示、状态映射、颜色映射和多实体组合。
5. 专用智能家居控制组件。

六、近期实施重点
----------------
已完成：项目版本号、导入导出、结构校验、敏感字段脱敏、自动备份、备份恢复、最多50步的编辑器撤销和重做、串口设备识别、烧录前目标确认、烧录后的设备重连和MAC核对、浏览器端崩溃恢复草稿，以及可写入ESPHome元数据的固件版本号。

下一步优先实现：
1. 烧录后通过ESPHome API或局域网设备信息查询核对运行中的固件版本。
2. 串口监视器和诊断日志。
3. 图片、字体和固件资源占用分析。

七、验收标准
------------
1. 老项目可以继续打开，不丢失页面、组件或图片引用。
2. 项目可以导出到本地文件，并可重新导入恢复。
3. 默认导出文件不包含明文 Wi-Fi 密码、API 密钥或 OTA 密钥。
4. 非法或损坏的项目文件不会覆盖当前项目，并显示明确错误。
5. 自动保存会保留最近20份项目备份，备份可以从工作台恢复。
6. 后端单元测试全部通过。
7. 前端 JavaScript 语法检查通过。
8. 生成的 ESPHome 配置继续通过已有测试，且原有编译、烧录流程不回归。
9. 烧录任务必须绑定已识别并确认的串口，设备被占用时返回可读错误。
